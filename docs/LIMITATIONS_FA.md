# دامنه آزمون و محدودیت‌های مهم

## مواردی که در محیط آفلاین آزموده شده‌اند

- نصب و import کتابخانه در Python محیط ساخت.
- پارسر API جدید (`GetMarketWatch`، `GetMarketOverview`، `GetClosingPriceDailyList`، `GetPriceAdjustList`) و پارسر سایت قدیم روی **نمونه پاسخ‌های واقعی ضبط‌شده از TSETMC** آزموده شدند: ۲٬۶۸۲ ردیف دیده‌بان جدید، ۱٬۴۱۹ ردیف دیده‌بان قدیم، عمق ۵ سطح و تطبیق دارایی پایه برای همه اختیارها.
- ارتقای خودکار پایگاه نسخه 1.0 به ساختار جدید، با نگهداری نسخه پشتیبان.
- وارد کردن ۶٬۹۴۹ شناسه از فایل اصلی `TDA` به SQLite.
- باقی‌ماندن شناسه منقضی پس از حذف از snapshot روز؛ اضافه‌شدن رکورد جدید بدون حذف قدیم.
- فیلتر نوع‌های نماد، خواندن سطوح سفارش، پارس تاریخ سررسید شمسی به میلادی.
- دریافت تاریخچه آزمایشی، نادیده گرفتن روز بدون معامله، تعدیل قیمت با ضرایب آزمایشی.
- UPSERT قیمت‌ها بدون ثبت تکراری، ذخیره/بازیابی آفلاین، گزارش خطای نماد، خروجی تک‌شیت TDA.

## مواردی که امکان آزمون زنده نداشته‌اند

- موفقیت اتصال زنده فعلی به `cdn.tsetmc.com` (و در صورت نیاز `old.tsetmc.com`). پارسرها با نمونه پاسخ واقعی آزموده شده‌اند، ولی پاسخ امروز سرور از این محیط قابل دریافت نبود.
- اینکه `GetMarketWatch` جدید همه ابزارها (به‌ویژه آتی و مشتقات کالایی) را پوشش می‌دهد یا نه.
- سازگاری قطعی فرمت پاسخ وب‌سایت در تاریخ استفاده شما با نمونه‌های کد اولیه.
- کامل‌بودن پوشش نمادهای بورس، فرابورس، اختیارها و آتی در هر ساعت/بازار.
- دقت ضرایب تعدیل واقعی برای همه رویدادها و همه دسته‌های دارایی.
- سقف مجاز تعداد درخواست‌ها، نیاز به IP داخل ایران یا موانع شبکه‌ای سرویس.

به همین دلیل، آماده‌بودن **کد نصب‌پذیر و تست‌شده آفلاین** به معنای تضمین دسترسی آنلاین در شرایط شبکه واقعی نیست.

## ملاحظات داده و صحت مالی

۱. `Close` همان `pClosing` (قیمت پایانی، مبنای قیمت روز بعد) و `Last` همان `pDrCotVal` (آخرین معامله) است. این نام‌گذاری در snapshot، مشتقات و تاریخچه یکسان است.

۲. آرشیو قیمت هر شناسه فقط از زمانی قابل پرشدن است که API آن تاریخچه را هنوز در دسترس قرار دهد. برای قراردادهای منقضی‌شده، اجرای زودهنگام و دوره‌ای آرشیو ضروری است.

۳. قراردادهای جدید مشتقه ممکن است الگوی نام‌گذاری متفاوتی داشته باشند؛ ردیف‌ها حذف نمی‌شوند اما `Strike`، `Expiry` یا `Underlying` برای بعضی قراردادها ممکن است خالی بماند.

۴. نگهداری روزهای بدون معامله انتخاب کاربر است (`traded_only`). پیش‌فرض این است که همه روزها ذخیره شوند. اگر sync را با `traded_only=True` اجرا کنید، آن روزها هرگز ذخیره نمی‌شوند و بعداً فقط با دریافت دوباره از سرور (اگر هنوز ارائه شود) قابل بازیابی‌اند.

۵. پارامتر `last=0` دقیقاً مطابق فایل اولیه به API ارسال می‌شود. بدون اتصال زنده، نمی‌توان ادعا کرد سرور در همه شرایط همواره کل تاریخچه را برمی‌گرداند. پوشش هر شناسه را با کوچک‌ترین و بزرگ‌ترین تاریخ ذخیره‌شده بررسی کنید.

۶. خروجی `market.snapshot` ممکن است در زمان تعطیلی بازار شامل داده آخرین روز معاملاتی باشد. برای تشخیص روز داده از `overview()["LastTradeDate"]` و `TSE_Situation` استفاده کنید.

۶-۱. API جدید دیده‌بان، نوع ابزار (`Type`) و بازار (`MarketType`) را برنمی‌گرداند. این دو از آرشیو محلی تکمیل می‌شوند. برای شناسه تازه، `GetInstrumentInfo` صدا زده می‌شود (حداکثر ۳۰۰ شناسه در هر snapshot، با کش). اگر آن هم در دسترس نباشد، فقط اختیارها از روی نام (`اختیارخ`/`اختیارف`) شناسایی می‌شوند و بقیه `Type` خالی می‌ماند تا اجرای بعدی.

۷. اجرای با `workers` بالا یا `min_interval` کم ممکن است باعث نرخ بیش‌ازحد درخواست و مسدودشدن منبع شود. با `workers=2..3` و `min_interval>=0.2` شروع کنید.

۸. **عدم آرشیو خودکار:** پس از نصب، برنامه هر روز خودکار اجرا نمی‌شود. برای تداوم واقعی، لازم است فرمان sync را به Task Scheduler/cron متصل کنید و گزارش خطاها را پیگیری کنید.

۹. تمام شناسه‌های داده پایه موجود حفظ شده‌اند، اما ۱٬۹۶۷ رکورد فایل اولیه اطلاعات پایه ناقص داشتند. این نسخه مقدار مفقود را جعل نمی‌کند؛ در صورت دیده‌شدن دوباره نماد در تابلو، آن را تکمیل می‌کند.

۹-۱. شناسه‌ها همه‌جا متن هستند. فایل CSV را اگر در Excel باز کنید، Excel شناسه‌های بلند را به عدد تبدیل و خراب می‌کند. برای استفاده در Excel از خروجی `.xlsx` کتابخانه (`to_excel` یا `--out file.xlsx`) استفاده کنید.

۱۰. اگر گواهی SSL یا ساختار API تغییر کرد، `TSETMCClient` خطای قابل مشاهده می‌دهد. برای «رفع مشکل» به‌صورت پیش‌فرض اعتبارسنجی SSL غیرفعال نشده است.

## معیار پذیرش میدانی پیشنهادی

پس از نصب در شبکه‌ای که به TSETMC دسترسی دارد، سه تست انجام شود: `mtse ... watch --limit 3`، `mtse ... options --kind call`، و `mtse ... sync --id <شناسه معتبر>`، سپس تعداد ردیف‌ها و تاریخ‌ها با سایت رسمی بررسی شود. اگر snapshot parse نشود، نمونه پاسخ و طول ردیف‌ها باید ثبت و parser با نسخه فعلی API تطبیق داده شود.
