# معماری، نگهداری داده‌ها و چرخه عملیات

## نمودار جریان اطلاعات

```text
cdn.tsetmc.com  ClosingPrice/GetMarketWatch ──► parse_market_watch ──► Market.snapshot ──► DataFrame
   (پیش‌فرض)                                         ▲                    │
                  Type/MarketType ◄── آرشیو SQLite ──┤                    └──► Derivatives.options/futures
                                  └── GetInstrumentInfo (فقط شناسه تازه، با کش)
old.tsetmc.com  MarketWatchInit (فقط old/auto) ──► parse_watch ─┘
                           ▼
      Archive.merge_instruments ──► SQLite: instruments ──► TDA.xlsx (تنها شیت TDA، شناسه = متن)
                                                │

                                                │
           cdn.tsetmc.com GetClosingPriceDailyList ◄─┘
                       │
```

## ساختار ذخیره‌سازی

- `instruments`: `instrument_id` کلید یکتا، `ticker`، `name`، `type`، `market_type`، `industry`، `stock_qty` و بقیه فیلدهای TDA؛ زمان اولین/آخرین رؤیت.
- `prices`: کلید ترکیبی `(instrument_id, date)`؛ ستون‌های `open`, `high`, `low`, `close` (=pClosing)، `last` (=pDrCotVal)، `prev_close`، `volume`، `value`، `trades`. نسخه ساختار در `PRAGMA user_version` (فعلاً 2) ثبت می‌شود؛ پایگاه نسخه 1.0 در اولین اجرا خودکار ارتقا می‌یابد و پیش از آن یک کپی `.v1-backup.sqlite` کنارش ساخته می‌شود.
- `adjustments`: ضریب تعدیل رویدادی به شناسه و تاریخ؛ به‌صورت مستقل از قیمت خام.
- `synchronization`: تاریخ آخرین تلاش، وضعیت، تعداد ردیف دریافت‌شده، پیام خطا و زمان دریافت ضرایب.

**قاعده هویت:** شناسه‌ها همیشه TEXT هستند (هرگز عدد/float). `Ticker` و `Name` هنگام ورود با حروف فارسی ی/ک ذخیره می‌شوند و جست‌وجو با `ticker_key` (بدون فاصله و نیم‌فاصله) انجام می‌شود. از نام نماد به‌تنهایی به‌عنوان کلید ذخیره‌سازی استفاده نمی‌شود. رکوردهای مربوط به قراردادهای مختلف اختیار یا نمادهای با نام مشابه با `instrument_id` جدا می‌شوند.

## چرخه پیشنهادی بهره‌برداری

۱. **یک بار هنگام راه‌اندازی:** ساخت SQLite و ورود TDA موجود؛ انجام backfill برای شناسه‌های شناخته‌شده. به دلیل انقضای قبلی بعضی قراردادها، ممکن است بخشی از تاریخچه قدیمی دیگر توسط سرور ارائه نشود.

۲. **پس از هر روز معاملاتی:** دریافت snapshot جدید؛ ثبت شناسه‌هایی که برای اولین بار دیده شده‌اند؛ ارسال درخواست تاریخچه برای همه شناسه‌های لازم با تأخیر کنترل‌شده و محدودیت تکرار.

۳. **هر زمان نیاز بود:** خواندن تاریخچه از SQLite حتی در روزهای عدم دسترسی به شبکه. قیمت تعدیل‌شده آفلاین فقط اگر ضرایب قبلاً ذخیره شده باشند ارائه می‌شود.

۴. **پشتیبان‌گیری:** فایل SQLite با ابزار backup و گزارش sync به مقصدی پایدار منتقل شوند. Excel برای کاربری انسانی قابل خروجی گرفتن است، ولی جایگزین SQLite نمی‌شود.

## طراحی برای خطا و انقضا

- HTTP با timeout و retry محدود (شامل 403، 429 و 5xx)؛ هیچ حلقه درخواست بی‌نهایت نیست. فاصله حداقلی درخواست‌ها (`min_interval`) بین همه workerها مشترک است.
- نوشتن در SQLite از مسیر یک قفل واحد انجام می‌شود تا workerهای موازی خطای `database is locked` نگیرند.
- نمونه‌ای از شکست یک نماد، موجب حذف یا پاک‌سازی داده موفق قبلی آن نمی‌شود.
- داده روز جدید به‌صورت UPSERT وارد جدول قیمت می‌شود؛ تاریخچه پیشین بدون پاسخ جدید حفظ می‌شود.
- نگهداری `synchronization` امکان تشخیص نمادهای مشکل‌دار و گزارش تکرار دریافت را فراهم می‌کند.
- `min_hours` برای کم‌کردن دریافت‌های تکراری است، **نه تضمین آرشیو تمام روزهای نماد**؛ اگر سرور تاریخچه‌ای را از دست بدهد، هیچ راهکار صرفاً مبتنی بر API آن را بازسازی نمی‌کند.
- برای پایداری بیشتر در مقیاس ۱۰هزار نماد، محدودیت تعداد worker، فواصل درخواست و زمان‌بندی مناسب پیشنهاد می‌شود.

## محدودیت «دریافت برخط»

کتابخانه به‌صورت پیش‌فرض `GetMarketWatch` (API جدید) را درخواست و یک snapshot برمی‌گرداند. این پیاده‌سازی پخش WebSocket، ثبت تیک‌های بازار، آرشیو لحظه‌ای عمق سفارش و زمان‌بندی خودکار را شامل نمی‌شود. برای داده قیمت تاریخی، منبع `GetClosingPriceDailyList` استفاده می‌شود، نه بازسازی قیمت از snapshot.

## نکته ضرایب تعدیل

در کد اولیه کاربر، `pClosing / pClosingNotAdjusted` به‌عنوان ضریب رویداد استفاده شده بود. این نسخه همان انتخاب منبع را نگه داشته و برای هر روز معاملاتی، حاصل ضرب ضرایب رویدادهای **پس از آن روز** را اعمال می‌کند تا داده تاریخی نسبت به آخرین مبنا تعدیل شود. معنا و صحت مالی هر رویداد وابسته به داده TSETMC است؛ برای موارد خاص مثل افزایش سرمایه، سود نقدی، تغییر مبنا و ابزار مشتقه، کنترل نمونه با مرجع معتبر ضروری است.
