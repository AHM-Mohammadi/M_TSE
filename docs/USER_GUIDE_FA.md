# راهنمای جامع نصب و استفاده از M_TSE — نسخه 1.2.0

## ۱. هدف و دامنه

این کتابخانه ابزار استاندارد پایتون برای دریافت داده TSETMC و نگهداری بلندمدت آن است. سه گروه داده را پوشش می‌دهد:

۱. **بازار برخط:** هر ردیف قابل مشاهده از تابلوی TSETMC، نوع ابزار، حجم/ارزش معاملات، قیمت پایانی و آخرین، ۵ سطح عرضه/تقاضا و وضعیت شاخص‌های کلی بازار.

۲. **مشتقات برخط:** اختیار خرید، اختیار فروش، آتی و ابزارهای مشتقه کالایی (در حد اطلاعات موجود در منبع تابلوی بازار). برای اختیارهای متناسب با الگوی نام‌گذاری اولیه، دارایی پایه، قیمت اعمال، تاریخ سررسید و فاصله روز تا سررسید استخراج می‌شود.

۳. **تاریخچه و آرشیو:** دریافت قیمت روزانه OHLCV به‌صورت تعدیل‌نشده یا با اعمال ضرایب اعلامی TSETMC؛ نگهداری شناسه‌های تاریخی و ذخیره قیمت‌های روزانه در SQLite حتی پس از خروج نماد از تابلوی روز.

**دو لایه اطلاعات مستقل هستند:** `Ticker Data Archive.xlsx` تنها شناسه و مشخصات پایه را در شیت `TDA` نگه می‌دارد؛ داده‌های قیمت در `tse_archive.sqlite` ذخیره می‌شوند. فایل Excel محل ذخیره قیمت نیست.

## ۲. پیش‌نیازها

- Python نسخه ۳.۱۰ یا بالاتر؛ ویندوز ۱۰/۱۱، لینوکس یا macOS.
- دسترسی HTTPS به `cdn.tsetmc.com` (API جدید TSETMC) برای دریافت زنده. سایت قدیم `old.tsetmc.com` فقط به‌عنوان منبع جایگزین اختیاری استفاده می‌شود. ممکن است در برخی شبکه‌ها این دامنه‌ها مسدود باشند یا ساختارشان تغییر کند.
- فضای ذخیره‌سازی مناسب: بسته اولیه شامل حدود ۶٬۹۴۹ شناسه است؛ حجم پایگاه داده با دانلود سوابق افزایش می‌یابد.
- برای بار نخست، اینترنت جهت نصب وابستگی‌ها در صورت نبودن آن‌ها لازم است.

## ۷. تاریخچه خام، تعدیل‌شده و گروهی

```python
# با نماد معاملاتی (فقط اگر یکتا باشد)
history = tse.history.fetch(ticker="خودرو", adjusted=False)

# برای شناسه‌های قدیمی و نمادهای تکراری، این روش مطمئن‌تر است
rows = tse.history.fetch(instrument_id="65883838195688438", adjusted=False)
rows_adj = tse.history.fetch(instrument_id="65883838195688438", adjusted=True)

# دریافت چند شناسه: خطاهای جزئی را در last_errors ببینید
batch = tse.history.fetch_many(
    instrument_ids=["65883838195688438", "00000000000000000"],
    adjusted=False, workers=3, on_error="skip")
print(tse.history.last_errors)
```

**شناسه را همیشه به‌صورت متن (داخل کوتیشن) بدهید.** شناسه‌ها ۱۴ تا ۱۹ رقم دارند و اگر به float یا سلول عددی Excel تبدیل شوند، رقم‌های آخرشان خراب می‌شود. کتابخانه شناسه float را با خطای روشن رد می‌کند.

این شناسه‌ها در مثال صرفاً **نمونه ورودی** هستند و در لحظه اجرا ممکن است معتبر یا پاسخ‌گو نباشند. برای انتخاب شناسه معتبر از `tse.archive.find("خودرو")` استفاده کنید. در حالت تعدیل‌شده از `GetPriceAdjustList` استفاده می‌شود؛ ضریب‌های رویدادها در تاریخچه عقب‌گردی اعمال می‌شوند، و حجم، ارزش معاملات و تعداد دادوستدها تعدیل نمی‌شوند.

نام ستون‌های قیمت در همه ماژول‌ها یکسان است:

- `Close` = `pClosing`: **قیمت پایانی**، یعنی میانگین وزنی قیمت معاملات روز که مبنای قیمت روز بعد است.
- `Last` = `pDrCotVal`: آخرین قیمت معامله‌شده.
- `Open`، `High`، `Low`، `PrevClose` (قیمت پایانی روز قبل)، `Volume`، `Value`، `Trades`.
- `Date` میلادی و `JDate` شمسی (مثل `1405/08/12`).

### روزهای بدون معامله: انتخاب با شماست

به‌صورت پیش‌فرض **همه روزهایی که سرور برمی‌گرداند** دریافت و در SQLite ذخیره می‌شوند، حتی روزهایی که نماد معامله نشده (`Trades == 0`). به این ترتیب هیچ داده‌ای غیرقابل‌برگشت دور ریخته نمی‌شود.

```python
# پیش‌فرض کل کتابخانه
tse = M_TSE(data_dir="tse_data")                      # همه روزها
tse = M_TSE(data_dir="tse_data", traded_only=True)    # فقط روزهای دارای معامله

# یا برای هر فراخوانی جداگانه
tse.history.fetch(ticker="خودرو", traded_only=True)
tse.backfill(types=["CallOption"], traded_only=True)        # فقط روزهای معامله‌شده ذخیره شود
tse.archive.history("65883838195688438", traded_only=True)  # فقط در خروجی پنهان شود
```

اگر همه روزها ذخیره شده باشند، با `traded_only=True` هنگام خواندن می‌توانید روزهای بدون معامله را پنهان کنید. این کار هر زمان قابل برگشت است.

## ۹. آرشیو قیمت‌ها و حفظ قراردادهای منقضی‌شده

```python
# ابتدا، تمام شناسه‌های روز را به آرشیو هویت اضافه کن
tse.update_tda()

# آرشیو دائمی همه شناسه‌ها، حتی اختیار منقضی‌شده
result = tse.backfill(workers=3, min_hours=12, refresh_adjustments=False)
result.to_csv("sync_report.csv", index=False, encoding="utf-8-sig")
print(result["status"].value_counts())
print(tse.archive.stats())
```

این کار **برای همه ۶٬۹۴۹ شناسه** و شناسه‌های افزوده‌شده اجرا می‌شود؛ بسته به سرعت شبکه می‌تواند بسیار طولانی باشد، و سرور ممکن است روی تعداد درخواست‌ها محدودیت بگذارد. در شروع، اجرای آزمایشی روی چند شناسه توصیه می‌شود:

```python
ids = tse.archive.instruments(types=["CallOption", "PutOption"]).index[:5].tolist()
report = tse.backfill(ids=ids, workers=2, refresh_adjustments=False)
```

`min_hours=12` در بازه ۱۲ ساعتِ بعد از آخرین دریافت موفق، نمادهای به‌روزشده را دوباره درخواست نمی‌کند. اگر خطا رخ دهد، وضعیت `failed` ثبت و نماد در اجرای بعدی دوباره قابل دریافت است. قیمت‌های گذشته هنگام خطا از پایگاه داده حذف نمی‌شوند.

`refresh_adjustments=True` باعث دریافت و نگهداری لیست ضرایب تعدیل می‌شود؛ تعداد درخواست‌ها را افزایش می‌دهد. برای قراردادهای کوتاه‌مدت می‌توان ضرایب را با درخواست مستقل فقط در صورت نیاز گرفت.

## ۱۲. نمونه سناریوهای کاربردی

**سناریوی A — سامانه رصد بازار:** هنگام نیاز، `snapshot(depth=True)` را به DataFrame منتقل و بر اساس `Type`، `Volume` و سفارش‌ها فیلتر کنید. این تابع snapshot است؛ جریان WebSocket و تیک‌به‌تیک نیست.

**سناریوی B — فیلتر و بررسی اختیارها:** `calls()` و `puts()` را بر اساس `DaysToExpiry`، `Strike` و قیمت مبنا تحلیل کنید. محاسبه نوسان ضمنی و Greeks بخشی از این کتابخانه نیست و باید به سیستم تحلیلی اضافه شود.

**سناریوی C — حفظ تاریخچه قراردادهای منقضی:** هر روز پس از بسته‌شدن بازار ابتدا `update-tda`، سپس `sync --all` یا sync انواع مورد نیاز را اجرا کنید. پس از تاریخ انقضا، داده قبلاً ذخیره‌شده در SQLite قابل استفاده خواهد بود؛ اما اگر سرور هرگز سابقه قراردادی را ارائه نکرده باشد، کتابخانه نمی‌تواند آن را بازسازی کند.

**سناریوی D — ساخت سیستم امتیازدهی:** با `archive.history` تاریخچه خام را در Jupyter دریافت کنید و اندیکاتورها و امتیازهای سفارشی خود را به آن اضافه کنید. هیچ تاریخچه‌ای نباید بر اساس یک نماد متنی مبهم به قراردادی دیگر نسبت داده شود.

## ۱۳. پشتیبان‌گیری، بازیابی و ریسک داده

- **فایل حیاتی:** `tse_archive.sqlite` حاوی قیمت‌ها و آرشیو شناسه‌هاست. `Ticker Data Archive.xlsx` فقط خروجی قابل‌خواندن شناسنامه است. از `tse.archive.backup("C:/Backup/tse_archive.sqlite")` برای بکاپ سازگار با WAL استفاده کنید.
- در هنگام کار با SQLite بهتر است برای پشتیبان‌گیری آنلاین از API بکاپ SQLite (`sqlite3.Connection.backup`) استفاده شود؛ کپی ساده فایل پایگاه فعال در حالت WAL می‌تواند ناقص باشد.
- بکاپ را خارج از پوشه پروژه و به‌صورت نسخه‌دار نگه دارید؛ روی سروری جداگانه در صورت امکان.
- برای بازگرداندن داده‌ها، پایگاه بکاپ‌گرفته‌شده را در پوشه داده هدف قرار دهید و سپس `status` اجرا کنید.
- تاریخ واقعی پوشش برای نمادهای منقضی وابسته به تاریخ آغاز جمع‌آوری و قابلیت منبع upstream است.
- اسکریپت‌ها را در Windows Task Scheduler با زمان پس از اتمام جلسه بازار اجرا کنید؛ اجرای خودکار در این بسته نصب یا فعال نشده است.

## ۱۴. رفع خطا

| مشکل | توضیح و اقدام |
|---|---|
| خطای `DataSourceError` یا 403/5xx | دسترسی شبکه و دامنه را بررسی کنید؛ ممکن است TSETMC مسدود/غیرفعال/متفاوت شده باشد. |
| `AmbiguousTicker` | از `tse.archive.find("...")` فهرست شناسه‌ها را ببینید و `instrument_id=` بدهید. |
| `Invalid instrument ID ... is a float` | شناسه را به‌صورت متن بدهید. اگر از CSV/Excel آمده، با `dtype=str` بخوانید. |
| API جدید جواب نمی‌دهد | موقتاً `market_source="auto"` یا `mtse --source old ...` را امتحان کنید. |
| `InstrumentNotFound` | `update_tda()` را اجرا کنید یا شناسه را مستقیم وارد کنید. |
| تاریخچه خالی | نماد ممکن است معامله نشده باشد یا سرور تاریخچه ندهد؛ با شناسه و گزارش `sync` کنترل کنید. |
| خطای تعدیل آفلاین | ابتدا `sync_one(..., refresh_adjustments=True)` انجام دهید. |
| فایل Excel باز است | Excel را ببندید و عملیات export را تکرار کنید؛ SQLite دست‌نخورده می‌ماند. |
| دستور CLI پیدا نمی‌شود | از `py -m M_TSE` یا محیط مجازی صحیح استفاده کنید. |
| `SQLite database is locked` | تعداد نویسندگان موازی را کم کنید؛ روی دیسک محلی اجرا کنید، نه پوشه همگام‌سازی شبکه‌ای. |

برای محدودیت‌های تأییدشده/تأییدنشده، `LIMITATIONS_FA.md` را بخوانید.

## ۱۵. اجرای روزانه با Windows Task Scheduler

اسکریپت نمونه `examples/daily_archive.py` پس از شروع ابتدا شناسه‌های TDA را به‌روز می‌کند، سپس تاریخچه قیمت **تمام** شناسه‌های آرشیوشده، شامل اختیارهای منقضی‌شده، را ثبت و در پایان گزارش CSV و بکاپ SQLite تولید می‌کند. فایل `daily_sync_windows.bat` همان فرایند را در فایل لاگ `logs/daily_archive.log` ثبت می‌کند.

برای تست دستی ابتدا به پوشه پروژه بروید و فرمان زیر را اجرا کنید:

```powershell
py examples\daily_archive.py
```

پس از تأیید موفقیت دانلود واقعی با شبکه و کنترل گزارش خطا، در Windows Task Scheduler یک Task با تناوب **روزانه، پس از پایان بازار** تعریف کنید و مسیر کامل `daily_sync_windows.bat` را به‌عنوان Program وارد کنید. زمان دقیق اجرا را متناسب با جلسات معاملاتی و زمان محلی سیستم تعیین کنید. نصب کتابخانه به‌خودی‌خود هیچ زمان‌بندی مخفی یا سرویس دائمی ایجاد نمی‌کند.

**نکته عملیاتی:** اولین backfill تمام شناسه‌های TDA ممکن است زمان‌بر باشد. گزارش `failed` را بررسی کنید؛ در هر اجرای بعدی نمادهای ناموفق دوباره امتحان می‌شوند. داده‌های موفق قدیمی حتی اگر نماد روز بعد در بازار حضور نداشته باشد حفظ خواهند شد.
